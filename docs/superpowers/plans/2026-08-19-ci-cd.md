# CI/CD for pharmacy-api and pharmacy-ui Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Gitea Actions CI/CD to `pharmacy-api` (.NET 10) and its `pharmacy-ui` submodule (Next.js 16), following the `main`+`dev`+`v*`-tag channel model already used by the `muna` project on the same Gitea host, with SSH-based auto-deploy to a test environment and optional ntfy notifications.

**Architecture:** Each repo gets two Gitea Actions workflows under `.gitea/workflows/`: a CI workflow (`build-and-test.yml`, runs on PR/push to `main`/`dev`) and a CD workflow (`publish-docker.yml`, runs on push to `dev` and on `v*` tags — builds and pushes a Docker image to the Gitea container registry, then auto-deploys the `dev` channel to a test box over SSH via `docker compose`). Each repo also gets a `docker-compose.prod.yml` describing how its image runs in production. pharmacy-ui additionally gets a new multi-stage `Dockerfile` (none exists today) and `output: 'standalone'` in `next.config.ts`.

**Tech Stack:** Gitea Actions (GitHub Actions-compatible syntax), Docker/Buildx, `docker/build-push-action@v6`, `docker/login-action@v3`, `actions/checkout@v4`, `actions/setup-dotnet@v4`, `actions/setup-node@v4`, `actions/cache@v4`, bash, curl (ntfy).

## Global Constraints

- Gitea host / registry: `git.samyeak.com.np`, namespace `siddhasoft` (from `docs/superpowers/specs/2026-08-19-ci-cd-design.md`).
- .NET version: `net10.0` everywhere in pharmacy-api (`PMS.sln` and all `*.csproj`).
- Node version: 22 (matches what's installed locally; use for both CI and the Dockerfile base image).
- Image names: `pms-api` (pharmacy-api) and `pharmacy-ui` (pharmacy-ui).
- Branch model: `main` (protected/release) + `dev` (auto-deploys to test); `v*` tags build a `release` channel image, production deploy is manual (out of CI scope).
- SSH deploy secrets are shared across both repos' workflows: `TEST_SSH_HOST`, `TEST_SSH_USER`, `TEST_SSH_KEY` (same test box), gated by repo variable `TEST_DEPLOY_ENABLED`. Deploy directories differ per repo: `TEST_DEPLOY_DIR` (api) vs `TEST_UI_DEPLOY_DIR` (ui).
- ntfy notification step is gated behind optional `vars.NTFY_URL` — must no-op (exit 0) when unset, per muna's pattern.
- No local .NET 10 SDK is available in this environment (only 8.0.423 via mise) and no network access to install one — CI workflow YAML for pharmacy-api cannot be executed locally end-to-end. Verify via YAML parsing (`python3 -c "import yaml; yaml.safe_load(open(...))"`) and by confirming referenced paths exist, not by running `dotnet build`/`dotnet test` locally.
- `pharmacy-ui` is a separate Gitea repo (git submodule at `pharmacy-ui/`). Its files are committed and pushed against its own `origin` remote, independent of pharmacy-api's history — use `git -C pharmacy-ui ...` for all git operations there, and `npm --prefix pharmacy-ui ...` for npm operations, to avoid changing the shell's working directory.
- `npm ci` requires network access to the npm registry, which the sandbox blocks by default — if it fails with a permission/network error, retry with the sandbox bypass (this is a local dependency install, not a destructive action).

### Task 1: pharmacy-api CI workflow

**Files:**
- Create: `.gitea/workflows/build-and-test.yml`

**Interfaces:**
- Produces: a `test` job (build+test) and a `notify` job, consumed by nothing else in this repo — Task 3 (CD workflow) is a separate trigger, not chained to this one.

- [ ] **Step 1: Create the CI workflow file**

```yaml
name: CI

on:
  pull_request:
    branches: [main, dev]
  push:
    branches: [main, dev]

jobs:
  test:
    name: Build & Test
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup .NET 10
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: 10.0.x

      - name: Cache NuGet packages
        uses: actions/cache@v4
        with:
          path: ~/.nuget/packages
          key: nuget-${{ runner.os }}-${{ hashFiles('**/*.csproj') }}
          restore-keys: nuget-${{ runner.os }}-

      - name: Restore
        run: dotnet restore PMS.sln

      - name: Build
        run: dotnet build PMS.sln --configuration Release --no-restore

      - name: Test
        id: test
        continue-on-error: true
        run: |
          mkdir -p TestResults
          dotnet test PMS.Tests/PMS.Tests.csproj \
            --configuration Release \
            --no-build \
            --logger "trx;LogFileName=PMS.Tests.trx" \
            --results-directory TestResults

      - name: Summarize test results
        id: summary
        if: always()
        run: |
          set -eo pipefail
          shopt -s nullglob globstar

          total=0; passed=0; failed=0; skipped=0; errors=0

          for f in TestResults/**/*.trx TestResults/*.trx; do
            [ -f "$f" ] || continue
            line=$(grep -oE '<Counters[^/]*/>' "$f" | head -n1 || true)
            [ -z "$line" ] && continue
            t=$( printf '%s' "$line" | grep -oE 'total="[0-9]+"'       | grep -oE '[0-9]+' || echo 0)
            p=$( printf '%s' "$line" | grep -oE 'passed="[0-9]+"'      | grep -oE '[0-9]+' || echo 0)
            fa=$(printf '%s' "$line" | grep -oE 'failed="[0-9]+"'      | grep -oE '[0-9]+' || echo 0)
            s=$( printf '%s' "$line" | grep -oE 'notExecuted="[0-9]+"' | grep -oE '[0-9]+' || echo 0)
            e=$( printf '%s' "$line" | grep -oE ' error="[0-9]+"'      | grep -oE '[0-9]+' || echo 0)
            total=$((total + t)); passed=$((passed + p)); failed=$((failed + fa))
            skipped=$((skipped + s)); errors=$((errors + e))
          done

          outcome="${{ steps.test.outcome }}"
          if [ "$outcome" = "success" ] && [ "$failed" -eq 0 ] && [ "$errors" -eq 0 ]; then
            status="passed"
          else
            status="failed"
          fi

          { echo "status=$status"; echo "total=$total"; echo "passed=$passed"
            echo "failed=$failed"; echo "skipped=$skipped"; echo "errors=$errors"
          } >> "$GITHUB_OUTPUT"

          {
            echo "## Unit Tests"
            echo "| Metric  | Count |"
            echo "|---------|-------|"
            echo "| Total   | $total |"
            echo "| Passed  | $passed |"
            echo "| Failed  | $failed |"
            echo "| Skipped | $skipped |"
            echo "| Errors  | $errors |"
          } >> "$GITHUB_STEP_SUMMARY"

      - name: Fail job if tests failed
        if: always() && steps.summary.outputs.status == 'failed'
        run: |
          echo "Tests failed: ${{ steps.summary.outputs.failed }} failed, ${{ steps.summary.outputs.errors }} errors"
          exit 1

  notify:
    name: Notify
    needs: [test]
    if: always()
    runs-on: ubuntu-latest

    steps:
      - name: Notify ntfy
        env:
          NTFY_URL: ${{ vars.NTFY_URL }}
          NTFY_TOKEN: ${{ secrets.NTFY_TOKEN }}
          EVENT: ${{ github.event_name }}
          REF: ${{ github.ref_name }}
          SHA: ${{ github.sha }}
          ACTOR: ${{ github.actor }}
          SERVER: ${{ github.server_url }}
          REPO: ${{ github.repository }}
          RUN_ID: ${{ github.run_id }}
          RESULT: ${{ needs.test.result }}
        run: |
          if [ -z "$NTFY_URL" ]; then
            echo "NTFY_URL variable not set; skipping notification."
            exit 0
          fi

          if [ "$RESULT" = "success" ]; then
            status="passed"; tags="white_check_mark,pharmacy-api,ci"; priority="default"
          else
            status="failed"; tags="x,pharmacy-api,ci"; priority="high"
          fi

          title="pharmacy-api CI: ${status} on ${REF}"
          body=$(printf 'Event:   %s\nBranch:  %s\nCommit:  %s\nActor:   %s\n\nTests: %s\n\nRun: %s/%s/actions/runs/%s' \
            "$EVENT" "$REF" "$SHA" "$ACTOR" \
            "$RESULT" \
            "$SERVER" "$REPO" "$RUN_ID")

          auth_args=()
          if [ -n "$NTFY_TOKEN" ]; then
            auth_args=(-H "Authorization: Bearer $NTFY_TOKEN")
          fi

          curl -sS --fail-with-body \
            -H "Content-Type: text/plain" \
            -H "Title: $title" \
            -H "Tags: $tags" \
            -H "Priority: $priority" \
            "${auth_args[@]}" \
            -d "$body" \
            "$NTFY_URL"
```

### Task 3: pharmacy-api CD workflow

**Files:**
- Create: `.gitea/workflows/publish-docker.yml`

**Interfaces:**
- Consumes: `docker-compose.prod.yml`'s `pms-api` service name (Task 2), the existing `Dockerfile` at repo root (unchanged).
- Produces: pushes `pms-api:dev`/`pms-api:dev-<sha>` (on `dev` push) or `pms-api:<version>`/`pms-api:latest` (on `v*` tag) to `git.samyeak.com.np/siddhasoft/pms-api`.

- [ ] **Step 1: Create the file**

```yaml
name: Publish Docker Image

# Two promotion channels:
#   * push to `dev`     -> build & push pms-api:dev (+ dev-<sha>), then
#                          auto-deploy to the testing env. No :latest.
#   * push tag `v1.2.3` -> build & push pms-api:1.2.3 + :latest (release).
#                          Production deploy is manual, not automated here.
on:
  push:
    branches: [dev]
    tags:
      - 'v*'

jobs:
  publish:
    name: Build & Push Image
    runs-on: ubuntu-latest

    env:
      REGISTRY: git.samyeak.com.np
      NAMESPACE: siddhasoft
      IMAGE_NAME: pms-api

    outputs:
      channel: ${{ steps.meta.outputs.channel }}

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Resolve image tags
        id: meta
        run: |
          set -eo pipefail

          IMAGE_BASE="${REGISTRY}/${NAMESPACE}/${IMAGE_NAME}"

          if [ "${{ github.ref_type }}" = "tag" ]; then
            RAW="${{ github.ref_name }}"
            VERSION="${RAW#v}"
            CHANNEL="release"
            if ! printf '%s' "$VERSION" | grep -Eq '^[A-Za-z0-9_][A-Za-z0-9._-]{0,127}$'; then
              echo "Invalid release tag: $VERSION"
              exit 1
            fi
            TAGS="${IMAGE_BASE}:${VERSION}
          ${IMAGE_BASE}:latest"
          else
            VERSION="dev"
            CHANNEL="dev"
            TAGS="${IMAGE_BASE}:dev
          ${IMAGE_BASE}:dev-${GITHUB_SHA::7}"
          fi

          {
            echo "channel=$CHANNEL"
            echo "version=$VERSION"
            echo "tags<<EOF"
            echo "$TAGS"
            echo "EOF"
          } >> "$GITHUB_OUTPUT"

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Login to Gitea container registry
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ secrets.REGISTRY_USER }}
          password: ${{ secrets.REGISTRY_TOKEN }}

      - name: Build and push
        id: build
        uses: docker/build-push-action@v6
        with:
          context: .
          file: Dockerfile
          platforms: linux/amd64
          push: true
          tags: ${{ steps.meta.outputs.tags }}

      - name: Summary
        if: always()
        run: |
          {
            echo "## Docker Image"
            echo ""
            echo "| Field   | Value |"
            echo "|---------|-------|"
            echo "| Channel | \`${{ steps.meta.outputs.channel }}\` |"
            echo "| Tags    | \`${{ steps.meta.outputs.tags }}\` |"
            echo "| Digest  | \`${{ steps.build.outputs.digest || 'n/a' }}\` |"
            echo "| Ref     | \`${{ github.ref }}\` |"
            echo "| SHA     | \`${{ github.sha }}\` |"
          } >> "$GITHUB_STEP_SUMMARY"

      - name: Notify ntfy
        if: always()
        env:
          NTFY_URL: ${{ vars.NTFY_URL }}
          NTFY_TOKEN: ${{ secrets.NTFY_TOKEN }}
          JOB_STATUS: ${{ job.status }}
          CHANNEL: ${{ steps.meta.outputs.channel }}
          REF: ${{ github.ref_name }}
          SHA: ${{ github.sha }}
          ACTOR: ${{ github.actor }}
          SERVER: ${{ github.server_url }}
          REPO: ${{ github.repository }}
          RUN_ID: ${{ github.run_id }}
        run: |
          if [ -z "$NTFY_URL" ]; then
            echo "NTFY_URL variable not set; skipping notification."
            exit 0
          fi

          if [ "$JOB_STATUS" = "success" ]; then
            title="pharmacy-api Docker: published ${CHANNEL} (${REF})"
            tags="whale,white_check_mark,pharmacy-api,docker"
            priority="default"
          else
            title="pharmacy-api Docker: FAILED ${CHANNEL} (${REF})"
            tags="whale,x,pharmacy-api,docker"
            priority="high"
          fi

          body=$(printf 'Channel: %s\nRef:     %s\nCommit:  %s\nActor:   %s\n\nRun: %s/%s/actions/runs/%s' \
            "$CHANNEL" "$REF" "$SHA" "$ACTOR" \
            "$SERVER" "$REPO" "$RUN_ID")

          auth_args=()
          if [ -n "$NTFY_TOKEN" ]; then
            auth_args=(-H "Authorization: Bearer $NTFY_TOKEN")
          fi

          curl -sS --fail-with-body \
            -H "Content-Type: text/plain" \
            -H "Title: $title" \
            -H "Tags: $tags" \
            -H "Priority: $priority" \
            "${auth_args[@]}" \
            -d "$body" \
            "$NTFY_URL"

  deploy-test:
    name: Deploy to testing env
    needs: publish
    # Only auto-deploy dev-channel images, and only when the testing env is
    # configured (set repo variable TEST_DEPLOY_ENABLED=true to opt in).
    # Release tags are deployed to prod manually/separately.
    if: needs.publish.outputs.channel == 'dev' && vars.TEST_DEPLOY_ENABLED == 'true'
    runs-on: ubuntu-latest

    steps:
      - name: Deploy over SSH
        env:
          SSH_HOST: ${{ secrets.TEST_SSH_HOST }}
          SSH_USER: ${{ secrets.TEST_SSH_USER }}
          SSH_KEY: ${{ secrets.TEST_SSH_KEY }}
          # Directory on the test box containing docker-compose.prod.yml + .env
          DEPLOY_DIR: ${{ vars.TEST_DEPLOY_DIR }}
        run: |
          set -eo pipefail

          if [ -z "$SSH_HOST" ] || [ -z "$SSH_KEY" ]; then
            echo "TEST_SSH_HOST / TEST_SSH_KEY not configured; skipping deploy."
            exit 0
          fi

          mkdir -p ~/.ssh
          printf '%s\n' "$SSH_KEY" > ~/.ssh/deploy_key
          chmod 600 ~/.ssh/deploy_key
          ssh-keyscan -H "$SSH_HOST" >> ~/.ssh/known_hosts 2>/dev/null

          ssh -i ~/.ssh/deploy_key "${SSH_USER}@${SSH_HOST}" \
            "cd '${DEPLOY_DIR}' && \
             docker compose -f docker-compose.prod.yml pull pms-api && \
             docker compose -f docker-compose.prod.yml up -d pms-api && \
             docker image prune -f"
```

# CI/CD

Both `pharmacy-api` (this repo) and `pharmacy-ui` (submodule, separate Gitea
repo) use Gitea Actions. Each has two workflows under `.gitea/workflows/`:

- `build-and-test.yml` — runs on every PR and push to `main`/`dev`. Builds,
  lints/tests, and posts a summary. Never pushes an image or deploys.
- `publish-docker.yml` — runs on push to `dev` (mutable "dev" channel) and
  on tags matching `v*` (immutable "release" channel). Builds and pushes a
  Docker image to the Gitea container registry, then — for the `dev`
  channel only — deploys it to a test server over SSH.

Production deploys are **manual**, not automated: after pushing a `vX.Y.Z`
tag and letting CI publish the image, deploy it yourself on the prod box
with `docker compose -f docker-compose.prod.yml pull && docker compose -f
docker-compose.prod.yml up -d`.

## Required secrets (set per repo, in each repo's Gitea Settings → Actions → Secrets)

| Secret | Used by | Purpose |
|---|---|---|
| `REGISTRY_USER` | both `publish-docker.yml` | Login to `git.samyeak.com.np` container registry |
| `REGISTRY_TOKEN` | both `publish-docker.yml` | Login to `git.samyeak.com.np` container registry |
| `TEST_SSH_HOST` | both `publish-docker.yml` | Test box address for the `deploy-test` job |
| `TEST_SSH_USER` | both `publish-docker.yml` | SSH user on the test box |
| `TEST_SSH_KEY` | both `publish-docker.yml` | Private key for the SSH user above |
| `NTFY_TOKEN` | both workflows, both repos | Optional — bearer token if your ntfy topic requires auth |

`TEST_SSH_HOST`/`TEST_SSH_USER`/`TEST_SSH_KEY` are the same test box for
both repos — set the same values in both the pharmacy-api and pharmacy-ui
Gitea repos.

## Required variables (Gitea Settings → Actions → Variables)

| Variable | Repo | Purpose |
|---|---|---|
| `TEST_DEPLOY_ENABLED` | both | Set to `true` to turn on the `deploy-test` job. Left unset/false, publish workflows build+push images but skip deploy. |
| `TEST_DEPLOY_DIR` | pharmacy-api | Path on the test box holding `docker-compose.prod.yml` + `.env` for the API |
| `TEST_UI_DEPLOY_DIR` | pharmacy-ui | Path on the test box holding `docker-compose.prod.yml` for the UI |
| `NTFY_URL` | both, both repos | Optional — ntfy topic URL. Left unset, the notify steps no-op. |
| `DEV_API_URL` | pharmacy-ui | `NEXT_PUBLIC_API_URL` baked into the `dev`-channel UI image |
| `PROD_API_URL` | pharmacy-ui | `NEXT_PUBLIC_API_URL` baked into `release`-channel UI images |

`DEV_API_URL`/`PROD_API_URL` are required for `pharmacy-ui`'s
`publish-docker.yml` to succeed — the workflow fails fast with a clear error
if the one it needs for the current channel is unset, since a missing
`NEXT_PUBLIC_API_URL` would otherwise bake `undefined` into the built
frontend.

## One-time test server setup

On the test box:

```bash
mkdir -p /opt/pharmacy-api /opt/pharmacy-ui   # or wherever you want them
# pharmacy-api:
cp docker-compose.prod.yml /opt/pharmacy-api/
cp .env.example /opt/pharmacy-api/.env        # then edit with real test values
# pharmacy-ui:
cp docker-compose.prod.yml /opt/pharmacy-ui/
```

Then set `TEST_DEPLOY_DIR=/opt/pharmacy-api` and
`TEST_UI_DEPLOY_DIR=/opt/pharmacy-ui` as Gitea repo variables.

Generate a dedicated SSH keypair for CI to use, add the public key to
`~/.ssh/authorized_keys` for the deploy user on the test box, and store the
private key as the `TEST_SSH_KEY` secret in both repos:

```bash
ssh-keygen -t ed25519 -f ./ci-deploy-key -C "gitea-ci-deploy" -N ""
```

Finally, log in to the Gitea container registry once from the test box (or
confirm `docker compose pull` can reach it) if the registry requires auth
for pulls as well as pushes.

```bash
git tag v1.2.3
git push origin v1.2.3
```

This builds and pushes `pms-api:1.2.3` + `pms-api:latest` (or
`pharmacy-ui:1.2.3` + `:latest` in the UI repo). It does **not** deploy —
do that manually on the prod box once you're ready.
```

### Task 9: pharmacy-ui CD workflow

**Files:**
- Create: `pharmacy-ui/.gitea/workflows/publish-docker.yml`

**Interfaces:**
- Consumes: `pharmacy-ui/Dockerfile`'s build args (Task 6), `docker-compose.prod.yml`'s `pharmacy-ui` service name (Task 8), repo variables `DEV_API_URL`/`PROD_API_URL` (documented in Task 4).
- Produces: pushes `pharmacy-ui:dev`/`pharmacy-ui:dev-<sha>` or `pharmacy-ui:<version>`/`pharmacy-ui:latest` to `git.samyeak.com.np/siddhasoft/pharmacy-ui`.

- [ ] **Step 1: Create the file**

```yaml
name: Publish Docker Image

# Two promotion channels:
#   * push to `dev`     -> build & push pharmacy-ui:dev (+ dev-<sha>), then
#                          auto-deploy to the testing env. No :latest.
#   * push tag `v1.2.3` -> build & push pharmacy-ui:1.2.3 + :latest (release).
#                          Production deploy is manual, not automated here.
on:
  push:
    branches: [dev]
    tags:
      - 'v*'

jobs:
  publish:
    name: Build & Push Image
    runs-on: ubuntu-latest

    env:
      REGISTRY: git.samyeak.com.np
      NAMESPACE: siddhasoft
      IMAGE_NAME: pharmacy-ui

    outputs:
      channel: ${{ steps.meta.outputs.channel }}

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Resolve image tags and API URL
        id: meta
        env:
          DEV_API_URL: ${{ vars.DEV_API_URL }}
          PROD_API_URL: ${{ vars.PROD_API_URL }}
        run: |
          set -eo pipefail

          IMAGE_BASE="${REGISTRY}/${NAMESPACE}/${IMAGE_NAME}"

          if [ "${{ github.ref_type }}" = "tag" ]; then
            RAW="${{ github.ref_name }}"
            VERSION="${RAW#v}"
            CHANNEL="release"
            if ! printf '%s' "$VERSION" | grep -Eq '^[A-Za-z0-9_][A-Za-z0-9._-]{0,127}$'; then
              echo "Invalid release tag: $VERSION"
              exit 1
            fi
            API_URL="$PROD_API_URL"
            TAGS="${IMAGE_BASE}:${VERSION}
          ${IMAGE_BASE}:latest"
          else
            VERSION="dev"
            CHANNEL="dev"
            API_URL="$DEV_API_URL"
            TAGS="${IMAGE_BASE}:dev
          ${IMAGE_BASE}:dev-${GITHUB_SHA::7}"
          fi

          if [ -z "$API_URL" ]; then
            echo "No API URL configured for channel '$CHANNEL' (set repo variable DEV_API_URL / PROD_API_URL)."
            exit 1
          fi

          {
            echo "channel=$CHANNEL"
            echo "version=$VERSION"
            echo "api_url=$API_URL"
            echo "tags<<EOF"
            echo "$TAGS"
            echo "EOF"
          } >> "$GITHUB_OUTPUT"

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Login to Gitea container registry
        uses: docker/login-action@v3
        with:
          registry: ${{ env.REGISTRY }}
          username: ${{ secrets.REGISTRY_USER }}
          password: ${{ secrets.REGISTRY_TOKEN }}

      - name: Build and push
        id: build
        uses: docker/build-push-action@v6
        with:
          context: .
          file: Dockerfile
          platforms: linux/amd64
          push: true
          build-args: |
            NEXT_PUBLIC_API_URL=${{ steps.meta.outputs.api_url }}
            NEXT_PUBLIC_APP_NAME=PharmaCare PMS
            NEXT_PUBLIC_APP_VERSION=${{ steps.meta.outputs.version }}
          tags: ${{ steps.meta.outputs.tags }}

      - name: Summary
        if: always()
        run: |
          {
            echo "## Docker Image"
            echo ""
            echo "| Field   | Value |"
            echo "|---------|-------|"
            echo "| Channel | \`${{ steps.meta.outputs.channel }}\` |"
            echo "| API URL | \`${{ steps.meta.outputs.api_url }}\` |"
            echo "| Tags    | \`${{ steps.meta.outputs.tags }}\` |"
            echo "| Digest  | \`${{ steps.build.outputs.digest || 'n/a' }}\` |"
            echo "| Ref     | \`${{ github.ref }}\` |"
            echo "| SHA     | \`${{ github.sha }}\` |"
          } >> "$GITHUB_STEP_SUMMARY"

      - name: Notify ntfy
        if: always()
        env:
          NTFY_URL: ${{ vars.NTFY_URL }}
          NTFY_TOKEN: ${{ secrets.NTFY_TOKEN }}
          JOB_STATUS: ${{ job.status }}
          CHANNEL: ${{ steps.meta.outputs.channel }}
          REF: ${{ github.ref_name }}
          SHA: ${{ github.sha }}
          ACTOR: ${{ github.actor }}
          SERVER: ${{ github.server_url }}
          REPO: ${{ github.repository }}
          RUN_ID: ${{ github.run_id }}
        run: |
          if [ -z "$NTFY_URL" ]; then
            echo "NTFY_URL variable not set; skipping notification."
            exit 0
          fi

          if [ "$JOB_STATUS" = "success" ]; then
            title="pharmacy-ui Docker: published ${CHANNEL} (${REF})"
            tags="whale,white_check_mark,pharmacy-ui,docker"
            priority="default"
          else
            title="pharmacy-ui Docker: FAILED ${CHANNEL} (${REF})"
            tags="whale,x,pharmacy-ui,docker"
            priority="high"
          fi

          body=$(printf 'Channel: %s\nRef:     %s\nCommit:  %s\nActor:   %s\n\nRun: %s/%s/actions/runs/%s' \
            "$CHANNEL" "$REF" "$SHA" "$ACTOR" \
            "$SERVER" "$REPO" "$RUN_ID")

          auth_args=()
          if [ -n "$NTFY_TOKEN" ]; then
            auth_args=(-H "Authorization: Bearer $NTFY_TOKEN")
          fi

          curl -sS --fail-with-body \
            -H "Content-Type: text/plain" \
            -H "Title: $title" \
            -H "Tags: $tags" \
            -H "Priority: $priority" \
            "${auth_args[@]}" \
            -d "$body" \
            "$NTFY_URL"

  deploy-test:
    name: Deploy to testing env
    needs: publish
    if: needs.publish.outputs.channel == 'dev' && vars.TEST_DEPLOY_ENABLED == 'true'
    runs-on: ubuntu-latest

    steps:
      - name: Deploy over SSH
        env:
          SSH_HOST: ${{ secrets.TEST_SSH_HOST }}
          SSH_USER: ${{ secrets.TEST_SSH_USER }}
          SSH_KEY: ${{ secrets.TEST_SSH_KEY }}
          # Directory on the test box containing docker-compose.prod.yml
          DEPLOY_DIR: ${{ vars.TEST_UI_DEPLOY_DIR }}
        run: |
          set -eo pipefail

          if [ -z "$SSH_HOST" ] || [ -z "$SSH_KEY" ]; then
            echo "TEST_SSH_HOST / TEST_SSH_KEY not configured; skipping deploy."
            exit 0
          fi

          mkdir -p ~/.ssh
          printf '%s\n' "$SSH_KEY" > ~/.ssh/deploy_key
          chmod 600 ~/.ssh/deploy_key
          ssh-keyscan -H "$SSH_HOST" >> ~/.ssh/known_hosts 2>/dev/null

          ssh -i ~/.ssh/deploy_key "${SSH_USER}@${SSH_HOST}" \
            "cd '${DEPLOY_DIR}' && \
             docker compose -f docker-compose.prod.yml pull pharmacy-ui && \
             docker compose -f docker-compose.prod.yml up -d pharmacy-ui && \
             docker image prune -f"
